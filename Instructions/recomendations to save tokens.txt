Чтобы ИИ (Claude или Gemini) не переписывал каждый раз `main.py` и `index.html` целиком и не сжигал дневной лимит токенов за 5 сообщений, нужно применить два инженерных приёма: **разделить монолитный код на независимые файлы (модули)** и **использовать дифф-промпты (Surgical Patch Prompts)**, которые строго запрещают ИИ выдавать весь файл целиком.

Ниже — пошаговый план, как организовать архитектуру файлов, на какие 7 независимых этапов разбить нашу спецификацию и какие шаблоны промптов использовать.

---

### Часть 1. Золотое правило экономии токенов: Разбей проект на модули

Пока у тебя весь фронтенд лежит в одном `index.html` на 1000 строк, а бэкенд — в одном `main.py`, ИИ вынужден каждый раз читать и генерировать тысячи строк кода даже ради замены цвета одной кнопки.

**Сделай из 2 больших файлов 6–7 маленьких (по 100–250 строк):**

```text
crm-project/
├── main.py              # Только запуск FastAPI и роуты (API endpoints)
├── database.py          # Подключение к Supabase и функции запросов к БД
├── ai_service.py        # Только логика OpenAI (голос, парсинг чеков)
└── static/ (или templates/)
    ├── index.html       # Только каркас (3 зоны экрана), без JS и стилей внутри!
    ├── styles.css       # Все стили (рамки визитов, бейджи Paid/Unpaid)
    ├── api.js           # Функции fetch() к бэкенду, автосохранение, сжатие фото
    └── app.js           # Логика дерева, вкладок, пересчёта сумм и рендера

```

**Почему это экономит до 80% токенов:** когда ты делаешь задачу по автосжатию фото, ты прикладываешь в чат **только** `api.js`. ИИ вообще не видит и не тратит токены на стили, верстку или OpenAI.

### Часть 2. Разбивка спецификации на 7 изолированных этапов (Спринтов)

Никогда не давай ИИ всю спецификацию сразу со словами «сделай это». Иди строго снизу вверх: сначала база данных, потом каркас, потом функции по одной.

| Этап | Название задачи | Что именно делаем (Scope) | Какие файлы трогаем |
| --- | --- | --- | --- |
| **Шаг 0** | **Модуляризация** | Выносим CSS и JS из `index.html` в отдельные файлы. Никакого нового функционала. | `index.html`, `styles.css`, `app.js` |
| **Шаг 1** | **Схема БД (Supabase)** | Пишем один SQL-скрипт, который создаёт/обновляет таблицы: `profile`, `clients`, `projects`, `visits`, `receipts`, `invoices` со всеми нужными полями. | Только SQL-редактор в Supabase (0 токенов на код приложения) |
| **Шаг 2** | **Каркас UI + Auto-Save + Inline Delete** | Делаем 3 фиксированные зоны экрана, дерево `Client → Project → Visit`, индикатор `Saving... -> Saved ✓` и двухшаговую кнопку удаления `Confirm Delete`. | `index.html`, `styles.css`, `app.js`, `main.py` |
| **Шаг 3** | **Профиль и Карточка клиента + Адреса** | Экран `My Profile` + поля клиента (`Email`, `Address` с бесплатным автозаполнением адресов). | `app.js`, `main.py` |
| **Шаг 4** | **Визиты, Статусы и Подсветка дат** | 4 статуса визита (`Scheduled`, `In Progress`, `Completed`, `Canceled`), поле `Time Spent`, жирный шрифт и голубая рамка (если до даты $\le 3$ дней). | `styles.css`, `app.js`, `main.py` |
| **Шаг 5** | **Цепочка `Planned Work → Estimate → Invoice**` | Переключатель Estimate (`Fixed` / `Hourly`), кнопка `+ Create Invoice` внутри визита (с обходом пустых шагов), статусы `Paid / Unpaid` и красные бейджи долгов в дереве. | `app.js`, `main.py` |
| **Шаг 6** | **Чеки (`Receipts`) и Модуль сжатия фото** | Тумблер `[+ Add to Invoice]`, клиентское сжатие фото до 1920px (WebP, ~300 КБ) в браузере и загрузка в Supabase Storage. | `api.js`, `app.js`, `main.py` |
| **Шаг 7** | **Финансовая аналитика (P&L Report)** | 4 плашки (`Revenue Paid`, `Unpaid`, `Expenses`, `Net Profit`) + `Estimate vs Invoice` с фильтром по датам в карточке клиента и глобальном отчёте. | `app.js`, `main.py` |

### Часть 3. Как составить промпт, чтобы ИИ не переписывал весь код

У языковых моделей есть «вредная привычка»: если не поставить жёсткое ограничение, они выплюнут весь файл на 500 строк, даже если поменялась одна функция.

Используй **двухуровневую систему промптов**:

#### 1. Стартовый промпт (кидается 1 раз в начале работы над задачей)

Его цель — задать правила игры и запретить переписывать файлы целиком.

> **Шаблон промпта (можно копировать как есть):**
> ```text
> МЫ РАБОТАЕМ В РЕЖИМЕ СТРОГОЙ ЭКОНОМИИ ТОКЕНОВ (SURGICAL CODE PATCHES ONLY).
> 
> Жёсткие правила для всех твоих ответов в этом чате:
> 1. КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО выводить файлы целиком (никаких полных main.py или index.html).
> 2. Выводи ТОЛЬКО те конкретные функции, блоки HTML или эндпоинты, которые нужно добавить или изменить.
> 3. Для каждого изменения указывай точную навигацию в формате:
>    - Файл: [имя файла]
>    - Где искать: [название функции / строка ДО изменения]
>    - Что вставить / на что заменить: [только новый кусок кода]
> 4. Не трогай и не рефактори существующий рабочий код, если он не относится к текущей микро-задаче.
> 5. Весь UI и переменные — строго на английском языке. Объяснения пиши кратко, без воды.
> 
> Сейчас я дам тебе ТЕКУЩУЮ ЗАДАЧУ №1 и только тот кусок кода, с которым мы работаем. Подтверди одним предложением, что правила приняты, и жди код.
> 
> ```
> 
> 

#### 2. Рабочий промпт для конкретного шага (Пример для Шага 4 — Визиты)

Вместо того чтобы скидывать всю спецификацию на 9 пунктов, ты вырезаешь из нашей финальной спецификации **только 1 пункт** и скидываешь **только нужный кусок файла**.

> **Пример рабочего промпта:**
> ```text
> ЗАДАЧА: Реализовать логику отображения и статусов Визита (Шаг 4).
> 
> Требования только для этой задачи:
> 1. У визита 4 статуса (переключение в 1 клик с автосохранением через PATCH /api/visits/{id}): Scheduled, In Progress, Completed, Canceled.
> 2. Поле Time Spent (часы) — сохраняется на лету при изменении (onblur / debounce).
> 3. Визуальные правила в списке визитов:
>    - Если статус Scheduled или In Progress и дата >= сегодня: текст жирный (font-weight: bold).
>    - Если статус Scheduled/In Progress и до даты визита от 0 до 3 дней: добавить голубую рамку (border: 2px solid #38bdf8).
>    - Если статус Completed или Canceled: убрать жирный шрифт и рамку. Для Canceled сделать серый зачёркнутый текст.
> 
> Вот моя текущая функция рендера проекта из app.js и роут из main.py:
> [ВСТАВЛЯЕШЬ ТОЛЬКО 30-50 СТРОК КОДА, ГДЕ РЕНДЕРИТСЯ ПРОЕКТ]
> 
> Напиши ТОЛЬКО новые/изменённые функции для app.js, CSS-классы и один PATCH-эндпоинт для main.py. Полные файлы не выводить!
> 
> ```
> 
>

### Часть 4. Ещё 3 практических лайфхака против пожирания токенов

1. **Правило «Один чат = Один этап (Шаг)»:**
Не веди разработку всех 7 шагов в одной длинной простыне переписки! Каждый раз, когда ты отправляешь сообщение, нейросеть заново перечитывает **всю историю текущего чата с самого верха** — и списывает за это токены. Закончил Шаг 2 (проверил, закоммитил в Git) $\rightarrow$ **открой новый чистый чат** для Шага 3.
2. **Не проси ИИ искать место в коде — используй `Ctrl + F` в VS Code:**
Когда ИИ выдаёт тебе только одну обновлённую функцию `function renderVisitCard(visit) { ... }`, просто нажми `Ctrl + F` в VS Code, найди старую `renderVisitCard` и замени её за 3 секунды. Это экономит тысячи токенов на каждом ответе.
3. **Сначала проверь в браузере, потом переходи к следующему шагу:**
Если на Шаге 4 вылезла ошибка в консоли браузера (`F12`), скинь в чат **только текст ошибки из консоли** и саму функцию (15 строк), а не весь проект.
